# Learnings

Pitfalls, banana skins, and gotchas found the hard way.

This is not a design archive and not a changelog. Every entry here exists because something cost real time or shipped
broken, and the same trap is likely to catch the next person. Read this folder before starting work; add to it when
you find a new one.

## How to use it

**Before starting**, skim the index below for anything touching your area. An entry is worth two minutes if it saves
one wrong fix.

**To write, update or index an entry**, follow `skills/learnings-skill/SKILL.md`: the bar, naming the file as the
trap, the scope, the entry shape, the one-line index rule, and updating instead of duplicating.

## Two scopes

Every entry carries a `**Scope:**` line, and the index is split to match. **Transferable** entries teach a rule that
would still hold in another project or stack; **this repository** entries need this project itself to understand or
apply: its tables, products, scripts, deployments or vendor-platform behaviour. Classify by the rule the entry
teaches, not by the incident that surfaced it.

## Transferable

The first rows were copied from the working architecture's origin repository by its bootstrap kit
(`skills/bootstrapping-a-project`, *Run the kit*); entries added here later are this project's own.

**The copied entries are kept exactly as the origin wrote them, on purpose.** The product names, file paths and
incidents in them are the origin's examples: they are the evidence that the trap is real, not instructions about this
project, and a path they name may not exist here. The rule each entry teaches is what applies. Do not rewrite them:
the kit's `--sync` keeps each one current only while it is unchanged here (an edited copy is left and reported), so
every project reads the same text and later entries can flow in.
